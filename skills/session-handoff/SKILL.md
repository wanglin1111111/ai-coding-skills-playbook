# 会话交接治理（Session Handoff）

长会话上下文会腐烂（注意力稀释/错误固化/压缩失真/角色漂移）。本技能：判断该不该交接 → 生成五项交接文档 → 验证新会话可续跑。

## 标准流程

### 第 1 步：腐烂信号检测

逐项核对五个信号，**任意两个为真 → 立即交接**：

| 信号 | 核查动作 |
|---|---|
| 重复提问 | 同一问题被问过 ≥2 次且答案不一致/答不上 |
| 旧约束丢失 | 早期明确过的约束（术语/边界/红线）被当前行为违反且无察觉 |
| 纠错无效 | 同一错误被指出 ≥2 次，仍在犯 |
| 目标漂移 | 出现无人要求的行为，或已放弃方案被重新捡起 |
| 压缩已发生 | 历史已被压缩/摘要（系统提示可见） |

**轮次兜底**（无信号也交接）：单任务 >30 轮、同一文件来回改 >5 次、会话跨过夜/隔天。

### 第 2 步：交接前现状实测

**不凭记忆写状态**。先跑一遍现状确认：
- 测试是否绿（跑当前测试套件）
- 关键文件是否落盘（ls/读头尾）
- 进行中的命令/进程状态
把实测结果记下来，作为文档第 2 节的事实基础。

### 第 3 步：按五项模板生成交接文档

```markdown
# HANDOFF: <任务名>
## 1. 目标与验收口径
<一句话说清要做什么>
验收标准（逐条可打勾）:
- [ ] ...
## 2. 当前状态
已完成（带文件/commit 指针）:
- ...
未完成（按优先级）:
- [P0] ...   ← 接手后第一步
- [P1] ...
## 3. 关键决策与理由
已决定 + 为什么:
- ...
**被否决的方案**（防翻转，最重要）:
- 否决 X，因为 ...
## 4. 坑与红线
坑（现象+根因+规避）:
- ...
红线（绝对不能动）:
- 文件/行为: ...
## 5. 下一步最小动作
接手后第一个动作，具体到命令/文件/行号:
$ <命令>  /  改 <文件>:<行> <做什么>
```

### 第 4 步：五项自检（一项缺 = 不可续跑）

| 项 | 检查判据 |
|---|---|
| 1 目标验收 | 验收标准每条可观察可打勾？ |
| 2 当前状态 | 全部来自第 2 步实测，非记忆？P0 是否存在？ |
| 3 决策与否决 | 有"被否决方案"条目？（没有=防翻转能力为零） |
| 4 坑与红线 | 红线具体到文件/行为？ |
| 5 下一步 | 具体到命令/文件/行号，不是"继续推进"？ |

### 第 5 步：落盘 + 复述验证

- 交接文档写入仓库（HANDOFF.md 或对应 issue），**不留聊天记录**
- 验证：开新会话，只喂文档，让它复述"目标+下一步"——复述对了才算交接成功；复述错 → 缺项，回第 3 步补
- 升级：第 3 节出现不可逆决策 → 转 ADR（project-memory-external）；第 4 节反复出现的坑（≥3 次）→ 评估固化为私有 skill

## 硬规则

- **任意两个腐烂信号触发即交接**，不等第三个；轮次兜底到线也交接——保质期按轮次算，不只按症状。
- **状态必须实测**：凭记忆写的"当前状态"与磁盘经常不一致，实测是唯一合法来源。
- **P0 必须可执行**：未完成项第一项必须是"跑X/读Y/改Z"级别的具体动作。
- **被否决方案必填**：第 3 节没有否决项 = 交接文档最大漏洞（新会话必然重新踩被否决的路）。
- **不复述不算交接**：新会话复述通过是交接完成的唯一判据；旧会话尾段注意力已稀释，禁止让旧会话自己写总结。
- **周期体检替代临期交接**：长任务每 15-20 轮主动更新第 2、5 节（轻量交接），既当腐烂探针，又让正式交接零成本。

## 与长期记忆的衔接

| 交接文档内容 | 升级去向 |
|---|---|
| 第 3 节不可逆决策 | → ADR（project-memory-external） |
| 第 4 节反复踩的坑（≥3次） | → 私有 skill |
| 文档本身 | 随仓库走（HANDOFF.md/issue），任务闭环后归档 |
