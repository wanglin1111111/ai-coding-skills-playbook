# 双轴代码评审（Dual-Axis Review）

"能跑"（测试过/无报错）≠"可信"（实现了承诺且做得规范）。第一原则：**不听实现者自述**——评审输入只有两个客观物：代码 diff + 规格/规范文件。

## 两轴定义

### 轴 1：规格轴（Spec）——做的是不是要的东西

输入：**规格文档 + 代码 diff**（不读实现者解释）。三个问题：
- 规格里每条，代码里找得到对应实现吗？（**防漏做**）
- 代码里每个行为，规格里找得到出处吗？（**防多做/自由发挥**）
- 规格明确"不做"的，代码里真的没做吗？（反向扫描）

### 轴 2：规范轴（Norms）——做得对不对

输入：**代码 diff + 规范文件**（CONTEXT.md 术语表 / ADR / 私有 skill 红线；不读实现者解释）。检查项：
- 命名/术语符合术语表吗？（词频比对）
- 模块深浅达标吗？（接口/行为比、参数膨胀、转发链——深模块判据）
- 错误处理/测试/日志符合团队规范吗？
- 安全基线：注入/越权/敏感数据踩线了吗？

## 标准流程

### 第 1 步：确定评审输入（缺一轴就不开评）

- 规格：规格文档/需求单/工单（规格轴输入）。找不到规格 → 规格轴报"无规格可评"，**这是最严重发现**，直接打回补规格
- 规范：CONTEXT.md / ADR 目录 / 私有 skill 红线。缺失项记为"规范轴降级运行"
- diff：git diff（指定范围）

### 第 2 步：两轴独立执行（互不干扰）

**机器场景**：起两个独立子 Agent，上下文互不共享——一个读了另一个的结论会被"先入为主"带偏（看到"质量不错"会放松规格警惕）。
**人审场景**：两个 reviewer 分工，一人只盯规格、一人只盯规范，**先独立出意见再合流**（防锚定）。

轴内子项尽量机器化：
- 规格轴：规格条目 vs 代码符号对应检查、"不做清单"反向扫描
- 规范轴：术语词频、接口宽度、红线模式匹配（静态检查先过，模型/人只看扫不出的）

### 第 3 步：各轴出结论（格式强制）

每轴结论必须是列表，**每条必须引用对象**：

```
[规格轴]
- PASS/FAIL: <规格条目N> ↔ diff 中 <文件:符号> | 依据: 规格原文"<...>"
[规范轴]
- PASS/FAIL: <规范条目> ↔ diff 中 <文件:行> | 依据: 规范原文"<...>"
```

只写"总体良好/建议优化"而不引条目 = 该轴结论无效，重跑。

### 第 4 步：合流裁决

| 两轴结果 | 裁决 |
|---|---|
| 双 PASS | 可信，可合入 |
| 任一 FAIL | 打回；**打回原因必须引用规格/规范条款**（引不出条款的"问题"不算 FAIL，算建议） |
| 两轴矛盾 | 升级人工仲裁（见下） |

**仲裁纪律**：依据规格/规范的具体条款裁决，**引不出条款的一方观点不成立——赢的是文档，不是人/职级**。

### 第 5 步：完整验收链定位

本技能是闭环的评审环节，前置于它的是：实现完成 → 机器回归（实现者不得改测试）。评审过后 = 合入判据。

## 迁移到人工 Code Review 制度

| 双轴设计 | 人工制度映射 |
|---|---|
| 规格轴 Agent | reviewer-A 只问"是不是需求要的"，只读需求单+diff |
| 规范轴 Agent | reviewer-B 只问"写得规不规范"，只读规范+diff |
| 互不干扰 | 两人独立出意见再合流，先不互相通气 |
| 不听自述 | PR 描述限 3-5 行只写"改了什么+为什么"，禁写"这是正确的因为…"；reviewer 打勾以自己跑过/读过对应代码为前提 |
| 条款仲裁 | tech lead 仲裁必须引用条款 |
| 轴内机器化 | 规格对应检查+红线扫描进 CI，reviewer 只看机器扫不出的 |

防走样三纪律：分工写进 PR 模板（两个 reviewer 字段各标职责）；解释与验证分离；仲裁靠条款不靠职级。

## 硬规则

- **不听实现者自述**：实现者的解释不是评审输入；对解释存疑时以代码实测为准。
- **两轴上下文隔离**：机器双 Agent 不共享上下文；人审先独立后合流。发现串通=评审作废重跑。
- **每条结论必须引用对象**（规格条目/规范条款 + 文件位置）；引不出对象的意见降级为"建议"，不计入裁决。
- **无规格可评 = 最高级 FAIL**：规格缺失不是"跳过规格轴"的理由。
- **打回必须引条款**：引不出条款的"问题"是建议不是打回理由。
- **仲裁赢的是文档**：裁决必须落到规格/规范原文条款，职级不产生论点。
