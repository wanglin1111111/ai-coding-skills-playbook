# 项目记忆外置（Project Memory External）

项目记忆滞留在会话里 = 新会话只能看到代码看不到"为什么"。两个载体：**CONTEXT.md**（术语+模块地图）与 **ADR**（不可逆决策）。本技能做三件事：初始化、体检、给维护节奏。

## 标准流程

### 第 1 步：盘点现状

- 找 CONTEXT.md / ADR 目录（常见位置：仓库根、docs/、.agents/）
- 存在 → 走体检（第 2 步）；不存在 → 走初始化（第 3 步）

### 第 2 步：体检（已有文件）

**CONTEXT.md 四项纪律检查**：

| 检查项 | 判据 | 不通过的报告措辞 |
|---|---|---|
| 术语绑标识符 | 每条术语有对应代码变量/函数/表名 | "X 条术语未绑标识符，是空话，删除或补绑" |
| 行数上限 | 全文 ≤ 100 行 | "已 N 行，超限：先砍代码里能自解释的条目" |
| 模块负向描述 | 每个模块一行有"不碰什么" | "M 个模块缺负向边界，补'不碰X'" |
| 四节结构 | 项目一句话/术语表/模块地图/关键约束 | "结构缺第 N 节" |

**ADR 三项纪律检查**：

| 检查项 | 判据 | 报告措辞 |
|---|---|---|
| 五段完整 | 状态/背景/决策/理由/后果 | "ADR-00N 缺'后果'段——只写收益的 ADR 是广告" |
| 否决项存在 | 理由段写明否决了哪个备选及为什么 | "ADR-00N 无否决项，防翻转能力为零，补强" |
| 编号不复用 | 废弃的 ADR 保留+状态标记 | "发现编号复用，历史链断裂" |

**输出维护报告**：逐项 通过/不通过 + 具体补全建议（可直接执行的编辑指令）。

### 第 3 步：初始化（无文件）

**CONTEXT.md 模板（四节封顶，初始化时 ≤ 40 行起步）**：

```markdown
# CONTEXT
## 1. 项目一句话
<一句话说清是什么、给谁用>
## 2. 术语表
| 术语 | 定义 | 代码标识符 |
|---|---|---|
## 3. 模块地图
| 模块 | 负责什么 | 不碰什么 |
|---|---|---|
## 4. 关键约束
- 技术栈锁定: ...
- 性能红线: ...
```

**ADR 模板（五段，全文 ≤ 1 屏）**：

```markdown
# ADR-001: <决策名>
## 状态   已接受 / 已废弃（被 ADR-00N 取代）
## 背景   两句话：为什么现在必须定
## 决策   一句话：决定了什么
## 理由   1-3 条：为什么选它 + 明确写出否决了哪个备选及为什么
## 后果   1-3 条：这个决定带来的代价
```

初始化动作：从代码库现有结构提取模块地图初稿；从 git log/README 提取候选术语（逐条问用户确认定义与标识符）；**不代用户写决策**——ADR 初稿只给模板，决策内容必须用户拍板。

### 第 4 步：给出维护节奏（每次体检/初始化都要带）

| 触发点 | 动作 |
|---|---|
| 拷问访谈（grill-requirements）结束 | 新术语→术语表；不可逆决策点→新 ADR |
| 评审发现 AI 用词混乱 | 该词补术语表（缺失报警） |
| 新会话"重新发明"已决策方案 | 补强对应 ADR 否决项；检查 ADR 在不在会被读到的位置 |
| 每 10 个工单或大重构前 | 重跑拷问：删过期术语、标废弃 ADR |
| 移交/新人/新模型入场 | CONTEXT.md 当第一份读物，读不懂处=要补处 |

### 第 5 步：接入 AI 自动加载

确认 CONTEXT.md 与 ADR 目录被加入工具的自动加载（AGENTS.md / CLAUDE.md / .cursorrules 引用），保证新会话开场即带术语表与决策史。未接入 → 报告里列为最高优先级补全项。

## 硬规则

- **术语不收"一次性概念"**：判据=未来会话会再遇到。绑不上代码标识符的术语不收。
- **CONTEXT.md 超 100 行必须先删后加**：超限加内容=制造流水账。
- **ADR 只记不可逆决策**：可逆的日常选择不记；"改数据格式/对外 API/技术栈/付费点/部署拓扑"才配 ADR。
- **ADR 不改原文**：决策错了 → 新 ADR 废弃旧的，原文保留。
- **体检报告必须可执行**：每条不通过项给出具体编辑建议（补哪行/删哪条），不写"建议优化"这类空话。
- **初始化不代写决策**：模板可以代填结构，决策内容必须用户确认。
