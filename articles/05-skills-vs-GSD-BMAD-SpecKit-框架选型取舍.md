# ⑤ skills vs GSD / BMAD / Spec-Kit：框架选型取舍

> 系列文章 5/8 · 人工智能编程技能库应用方法
> 源材料：Matt Pocock Skills（github.com/mattpocock/skills）README 的路线宣言 + 本机框架实践对比

## 一、两条路线的本质分歧

AI 辅助开发工具生态里，针对"如何让 AI 可靠地做项目"，存在两条路线：

**路线 A：接管整条流水线（GSD / BMAD / Spec-Kit 类）**
- 形态：一个框架规定完整流程——阶段、工件、模板、角色（产品经理 Agent、架构师 Agent……），用户把项目交给它跑
- 卖点：开箱即用的秩序感，新手不用自己设计流程
- 代价：**流程本身成了黑盒**。框架的每一步在做什么、为什么这么做，用户改不了也看不清

**路线 B：可组合的纪律卡片（skills 类）**
- 形态：一组小的、单一职责的纯文本指令文件，每个卡片解决一类问题（拷问需求/写 ADR/双轴评审），用户按需取用、自由组合、随时改写
- 卖点：**控制权在人**。每个纪律都是透明的纯文本，看一遍就懂，改起来零成本
- 代价：秩序感要自己攒——选哪些卡片、按什么顺序用，初期需要判断力

Matt Pocock 的 README 把分歧说得很直白：GSD/BMAD/Spec-Kit "try to help by owning the process. But while doing so, they take away your control and make bugs in the process hard to resolve."（它们通过接管流程来帮忙，但由此拿走了你的控制权，并且让流程本身的 bug 难以解决。）

## 二、"流程 bug 难解决"是路线 A 的结构性死穴

这是两条路线最实质的差异，值得展开：

1. **路线 A 的 bug 发生在流程层，不在代码层**。测试跑不过时，问题可能是"框架在第三阶段少生成了一节规格"——但用户既没有流程的源码级理解，也没有改流程的权限，只能整个换框架或绕过。
2. **路线 B 的 bug 发生在卡片层，而卡片就是那几行文本**。某卡片行为不对，打开看、改掉、生效——"绕行调试"的成本是分钟级。
3. **路线 A 的升级是订阅式的**（框架更新你被动接受），**路线 B 的演化是自主式的**（你的卡片随项目一起版本管理）。

对应到纪律表述：**出现异常可即时绕行调试**——这是路线 B 的公文要点（三）"实行纪律组合"的底层理由。

## 三、混装多个框架会发生什么冲突

实际团队里最常见的错误不是选错路线，而是**混装**：既装了 GSD 跑流程，又装了 Spec-Kit 生成规格，还让 skills 的评审卡介入。三类冲突：

| 冲突类型 | 表现 |
|---|---|
| **工件冲突** | 两个框架都要求写 spec，但模板不同、存放位置不同、命名不同——AI 会话里同时加载两套模板，生成的工件两边都不合规 |
| **流程冲突** | GSD 说"先走它的阶段 2"，Spec-Kit 说"先填它的 spec 文件"——AI 不知道听谁的，或者交替执行两套流程，产出双份冗余 |
| **纪律冲突** | 两套框架对同一件事（比如"什么时候算完成"）定义不同——验收标准漂移，评审无据可依 |

**选型纪律：一条流水线只认一个"流程主权者"。**可以混装的范围是"纪律卡片"（单一职责、不主张全流程的 skills），不可混装的是"流程框架"（主张完整流水线的 GSD/BMAD/Spec-Kit）。具体取舍：

- 小团队/个人项目：全路线 B，纪律卡片按需取用，流程自己定（最灵活）
- 需要新人快速上手的中团队：选一个路线 A 框架作为流程骨架，**关掉其他一切流程类框架**，只保留不冲突的纪律卡片
- 已经装了路线 A 又想用 skills 的：先审计两套框架的工件路径与阶段定义，重叠的部分二选一，把另一方对应能力砍掉（fork 后删，不是并存）

## 四、选型的四个判据

1. **流程 bug 你能改吗？** 不能 → 路线 A 在你的场景是死穴
2. **你的项目流程稳定吗？** 稳定且可复用 → 路线 A 的秩序感值这个钱；频繁变 → 路线 B
3. **团队里谁能修框架？** 路线 A 要求至少一人能读改框架源码/配置，没有这个人就别装
4. **上下文预算多少？** 路线 A 的完整工件链吃上下文很凶；小模型/短上下文窗口场景，路线 B 的按需加载更经济

## 五、小结

- 本质分歧：接管流程（秩序换控制权）vs 纪律卡片（控制权换秩序）
- 路线 A 的死穴是"流程层 bug 用户修不了"；路线 B 的代价是"秩序要自己攒"
- 混装的冲突在工件/流程/纪律三层，纪律只有一条：流程主权者唯一
- 选型判据：bug 可改性、流程稳定性、维护人、上下文预算
