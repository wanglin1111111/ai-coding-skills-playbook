# ④ 深模块设计：让 AI 写出能维护的代码

> 系列文章 4/8 · 人工智能编程技能库应用方法
> 源材料：Matt Pocock Skills（github.com/mattpocock/skills）中深模块纪律 + Ousterhout《软件设计哲学》

## 一、深模块是什么

Ousterhout 在《A Philosophy of Software Design》里给出的判据：**接口小、行为多的模块是深模块；接口和行为一样大的模块是浅模块。**

```
深模块：  [====大量行为====]   ← 接口（小）
           ████████████████
浅模块：  [行为]
           █████  ← 接口（大，和行为一样宽）
```

深模块的价值：使用者只需要知道一小块接口，就能获得一大块能力；内部实现怎么改都不影响使用者。浅模块则是"透明的管道"——接口暴露了全部内部结构，使用者被迫知道实现细节，改内部就必须改所有使用者。

## 二、为什么 AI 特别需要深模块约束

AI 生成代码有两个结构性倾向，恰好都制造浅模块：

1. **平铺倾向**：让 AI 实现一个功能，它倾向于生成一长串平级函数，每个函数做一小步，接口（函数列表）和行为一样宽——典型的浅模块堆叠。
2. **接口膨胀倾向**：为了"灵活"，AI 喜欢给函数加参数、加可选配置、加钩子——接口越来越大，但行为没有变多。每多一个参数，使用者的认知负担加一，而能力没增加。

人类工程师写浅模块时还有"顺手"的缓冲，AI 写浅模块是**默认行为**——不约束，它一定给浅模块。所以"深模块"在 AI 工作流里不是审美偏好，是硬约束。

## 三、怎么变成给 Agent 的硬约束

三条可写进技能文件/AGENTS.md 的规则：

### 规则 1：新增公共接口前，先问"能不能藏"

每个新函数/新导出在被写下之前过一道检查：
- 它的使用者需要它的内部细节吗？需要 → 浅了，把它和它要暴露的细节合并进一个深函数
- 它的参数是使用者必须决策的吗？不是（实现细节泄漏成参数）→ 藏进内部

### 规则 2：一个文件一个主接口

模块组织上，一个文件对外暴露的主入口尽量收敛到一个函数/一个类。"这个文件里所有函数都要被外部调用"是浅模块的文件级信号。

### 规则 3：接口变更是高危事件

改动任何公共接口（增删参数、改签名、移动导出）在 AI 工作流里的风险等级等同于"改数据格式"——必须走 ADR（文章②），因为所有下游使用者（包括未来的 AI 会话）都要跟着改。

### 给 Agent 的提示词形态

```
实现功能时遵循深模块纪律：
1. 每个新导出先回答：使用者是否被迫理解我的内部？是 → 合并/封装
2. 参数超过 3 个的函数：逐个问"使用者真的需要决策这个吗"
3. 倾向生成一个深入口 + 私有辅助，而不是多个平级公共函数
4. 改动现有公共接口时，先列出所有调用方，按 ADR 流程处理
```

## 四、如何定期扫描代码库找"该深化"的地方

深模块不是一次设计出来的，是持续"深化"出来的。扫描判据（按信号强度排序）：

| 信号 | 判据 | 动作 |
|---|---|---|
| **接口/行为比** | 导出函数数 ≥ 文件内总函数数的一半 | 候选浅模块：合并导出为深入口 |
| **参数膨胀** | 单函数参数 ≥ 4，其中 ≥ 2 个调用方总是传相同值 | 把恒定值藏进内部，或用配置对象收敛 |
| **转发链** | 函数 A 只是调 B 再调 C（自身逻辑 < 3 行） | A 是浅管道，调用方直接调深的那端，删 A |
| **重复调用序列** | 多个调用方以相同顺序调用同一组函数 | 这组函数该合成一个深入口 |
| **改动扩散度** | 改一个内部细节导致 ≥ 3 个文件跟着改 | 该处浅了：把变化点包进深接口后面 |

扫描可以半自动：接口/行为比、转发链、重复调用序列都能用静态分析（引用计数/调用图）批量出候选清单，人工（或 AI 辅助）逐条判断是否真的该深化。

## 五、深模块与 AI 可维护性的闭环

深模块对 AI 辅助开发的额外红利：**小接口 = 小上下文**。AI 改一个模块时，只需要把该模块的小接口读进上下文，不需要理解内部实现的全部历史；模块深化一分，未来每次会话的上下文负担就轻一分。浅模块则相反——每个使用者都被迫带着实现细节工作，AI 会话的上下文窗口被浅模块持续吞噬。

所以深模块纪律的完整表述是：**小接口藏大量行为，既保护人类维护者，也保护 AI 会话的上下文预算。**

## 六、小结

- 浅模块是 AI 生成的默认形态，不约束必然发生
- 三条硬约束：新接口先问"能不能藏"、一文件一主接口、接口变更走 ADR
- 定期扫描五个信号（接口/行为比、参数膨胀、转发链、重复序列、改动扩散度），半自动出候选清单
- 深模块 = 人类可维护性 + AI 上下文预算的双重保障
