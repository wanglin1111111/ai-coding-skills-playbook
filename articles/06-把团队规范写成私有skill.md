# ⑥ 把团队规范写成私有 skill

> 系列文章 6/8 · 人工智能编程技能库应用方法
> 源材料：Matt Pocock Skills（github.com/mattpocock/skills）"Hack around with them. Make them your own." + 本机技能工程实践

## 一、从个人经验到组织资产的路径

团队里最值钱的知识往往长这样："这个服务部署前必须重启 X，不然 Y 会挂""这个客户的接口有 30 秒限流，批量调必须节流""上次 Z 事故就是因为没做 W"。

这些知识的现状：在某个人的脑子里、某个群聊的聊天记录里、某次事故的复盘文档深处。AI 会话永远读不到它们——于是每个新会话都在重新踩同一个坑。

**私有 skill 就是把这些知识固化成 AI 能读的、随仓库走的指令文件。**路径：

```
反复踩的坑（3 次以上）
  → 写出"如果重来一次，正确动作序列是什么"
  → 固化成 SKILL.md（触发条件 + 动作步骤 + 红线）
  → 放进仓库 .agents/skills/（或等价目录）
  → 版本管理 + 评审 + 分发
```

## 二、什么样的坑值得固化

不是所有经验都值得做成 skill。筛选标准三条：

1. **重复性**：同一个坑踩了 3 次以上，或者同类坑（不同模块的同一模式）累计 3 次。一次性的坑写成 skill 是过度工程。
2. **动作序列可描述**：正确动作能写成 3-7 步的有序清单。只能描述为"要小心""要注意"的经验没有 skill 形态，它属于评审checklist。
3. **违反成本高**：违反该规范导致事故/回滚/长时间排障。违反成本低的规范靠口头提醒即可，不值得占上下文。

## 三、SKILL.md 的写法（团队规范特化版）

### frontmatter：触发条件决定生死

```yaml
---
name: deploy-gateway-checklist
description: >-
  网关服务部署前检查：重启依赖顺序/限流配置/回滚脚本。
  Use whenever the user 部署/发布/上线 gateway 相关服务, 或改网关配置.
  Not for: 其他服务的部署流程（各自有 skill）.
---
```

团队规范类 skill 的 description 比通用 skill 更要命——**触发不准 = 规范在关键时刻缺席**。写法纪律：
- 触发词覆盖团队黑话（"上线""发版""部署"都要列，因为不同人说不同词）
- 明确 Not for 边界，防止规范串味（网关的 checklist 不该在数据库部署时触发）

### 正文：动作序列 + 红线，不写背景故事

```markdown
# 网关部署检查

## 动作序列（按序执行，每步给出完成判据）
1. 重启依赖：X 先于 Y（判据：Y 的 health 端点返回 200）
2. 限流确认：批量接口节流 ≤ 30 rps（判据：配置 diff 显示 rate=30）
3. 回滚脚本就位：rollback.sh 存在且 < 24h（判据：ls -la 时间戳）

## 红线（违反即停）
- 未完成第 1 步判据，禁止进入第 2 步
- 回滚脚本缺失 = 本次部署取消，没有例外
```

两条纪律：
- **每步带完成判据**。"重启 X"是动作，"Y 的 health 返回 200"是判据——没有判据的步骤 AI 会自行脑补"应该好了"
- **红线写"没有例外"**。规范里写"一般建议""通常应该"，AI 在赶工时会自行豁免；写成不可豁免的硬约束，AI 才会停下来

## 四、随仓库版本管理：规范也要走评审

私有 skill 的治理方式等同于代码：

1. **存放位置**：跟被规范的对象同仓库（网关的 checklist 在网关仓库里），不放公共技能库——规范的生效范围应该和作用域一致
2. **变更走 PR**：改 skill = 改团队规范，必须评审。评审视角和代码不同：触发条件准不准、判据可观察吗、红线有没有豁免漏洞
3. **事故驱动更新**：每次事故复盘，第一个问题是"现有 skill 是否覆盖了这次事故？没有 → 新增；有但没触发 → 改 description；触发了但步骤不对 → 改正文"
4. **定期清理**：技术栈迁移后，旧规范的 skill 会静默失效变成误导源——每季度过一次 skill 清单，失效的删掉或标废弃

## 五、分发的边界

- **仓库内 skill**：随仓库 clone 生效，作用域=仓库，这是默认形态
- **组织级 skill**：跨仓库通用的规范（比如"所有服务必须有回滚脚本"）放组织级技能目录，各仓库引用
- **个人 skill**：只对自己生效的工作习惯，不进团队仓库

分发的核心纪律：**skill 的作用域必须 ≤ 规范的适用域**。把网关专属 checklist 发到组织级，等于让所有服务都被网关规范约束——规范污染。

## 六、小结

- 筛选三标准：重复性（≥3 次）、动作序列可描述、违反成本高
- frontmatter 触发条件是生死线：覆盖黑话 + 明确 Not for 边界
- 正文纪律：每步带完成判据，红线写成不可豁免
- 治理等同代码：PR 评审、事故驱动更新、定期清理失效项
- 作用域纪律：skill 作用域 ≤ 规范适用域
