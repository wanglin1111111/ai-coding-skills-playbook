# ② CONTEXT.md 与 ADR 的写法与维护节奏

> 系列文章 2/8 · 人工智能编程技能库应用方法
> 源材料：Matt Pocock Skills（github.com/mattpocock/skills）中项目记忆外置（CONTEXT.md / ADR）实践

## 一、问题：项目记忆滞留在会话记录里

AI 辅助开发有一个独特的记忆黑洞：需求澄清、技术选型、踩坑结论，全部发生在**会话上下文**里。会话一关（或上下文一被压缩），这些决策的依据就丢了——新会话的模型只能看到代码本身，看不到"为什么是这样"。

后果是三个具体症状：
1. **重复踩坑**：同一个问题在新会话里重新"发现"一遍
2. **术语漂移**：同一个概念在不同会话里叫不同名字，生成的代码里名词混乱
3. **决策翻转**：早期定过的技术方向，新会话里被"更合理"的新建议推翻，无人记得当初为什么没选它

解法只有一条：**把项目记忆从会话里搬出来，变成随仓库走的文件。**两个载体：CONTEXT.md（统一术语+项目地图）和 ADR（不可逆决策记录）。

## 二、CONTEXT.md 怎么写才不变成流水账

### 结构（四节封顶）

```markdown
# CONTEXT
## 1. 项目一句话   （一句话说清这个项目是什么、给谁用）
## 2. 术语表       （每行一条：术语 | 定义 | 代码中的标识符）
## 3. 模块地图     （每个顶层模块一行：负责什么 / 不碰什么）
## 4. 关键约束     （技术栈锁定、性能红线、合规要求，各一行）
```

### 防流水账的四条纪律

| 纪律 | 说明 |
|---|---|
| **只收"会反复用到的词"** | 术语表每条必须满足：未来会话会再次遇到这个词。一次性概念不收 |
| **术语必须绑标识符** | 每条术语写出它在代码里对应的变量/函数/表名。绑不上标识符的术语是空话，不收 |
| **模块地图写"不碰什么"** | 每模块一行的负向描述（"不碰支付"）比正向描述更能防止 AI 越界改代码 |
| **总行数 ≤ 100 行** | 超了就是流水账的开始。超限时先砍"代码里已经能自解释的条目" |

### 什么进 CONTEXT.md，什么不进

- **进**：领域黑话（"工单"在本项目指什么状态）、缩写、项目特有的命名约定、模块边界
- **不进**：架构细节（进 ADR）、临时调试结论（进会话/issue）、文档里已有且稳定的公开知识

## 三、ADR 写多细

ADR（Architecture Decision Record，架构决策记录）只记**不可逆决策**——数据格式、对外 API、技术栈选型、付费点、部署拓扑。可逆的日常选择（用哪个 util 函数）不记，记了就是噪音。

### 标准格式（五段，全文 ≤ 1 屏）

```markdown
# ADR-007: 消息队列选 RabbitMQ 而非 Kafka
## 状态     已接受 / 已废弃（被 ADR-012 取代）
## 背景     两句话：为什么现在必须做这个决定
## 决策     一句话：决定了什么
## 理由     1-3 条：为什么选它，明确写出否决了哪个备选及为什么
## 后果     1-3 条：这个决定带来的代价（必须写代价，只写收益的 ADR 是广告不是记录）
```

### 三条关键纪律

1. **必须写否决项**。"为什么不用 X"和"为什么用 Y"同等重要——这是防决策翻转的核心：新会话看到否决理由，就不会再提 X。
2. **只记当时可见的理由**。事后证明决策错了，不改 ADR 原文，另开 ADR 废弃它。ADR 是决策时刻的历史记录，不是活文档。
3. **编号永不复用**。被废弃的 ADR 保留状态标记，新决策永远拿新号。

## 四、维护节奏（什么时候更新/重跑）

记忆外置文件最大的死法不是写错，而是**停止更新后变成误导源**。维护绑定到既有工作节点，不新增专门仪式：

| 触发点 | 动作 |
|---|---|
| 拷问访谈（文章①）结束时 | 新术语 → CONTEXT.md 术语表；每个不可逆决策点 → 新 ADR |
| 代码评审发现 AI 用词混乱 | 该词补进术语表（这是术语表缺失的报警信号） |
| 新会话里模型"重新发明"了已决策的方案 | 对应 ADR 的否决项写得不够 → 补强；同时检查 ADR 是否在会被读到的位置 |
| 每 N 个工单（建议 10 个）或每次大重构前 | 重跑一次完整拷问（文章①五类清单），对照产出：过期术语删、过期 ADR 标废弃 |
| 项目移交/新人（或新模型）入场 | 以 CONTEXT.md 为第一份读物，读不懂的地方就是文件要补的地方 |

### 重跑拷问的时机判据（"什么时候该再拷问一遍"）

- 项目目标句（CONTEXT 第 1 节）你已经说不顺了
- 两个会话对同一模块职责的理解冲突
- 出现第 3 次以上的"这个为什么这么写"提问

## 五、与 AI 工具的衔接

- CONTEXT.md 应被加入 AI 工具的**自动加载清单**（AGENTS.md / CLAUDE.md / .cursorrules 等里引用它），保证每个新会话开场就带着术语表和模块地图
- ADR 目录同理：AI 在做选型类任务前应先读 ADR 目录，看到"已否决"就换路
- 这两个文件本身是纯文本 Markdown，模型可读可写可评审——这是它们优于"口头约定+群聊沉淀"的根本原因

## 六、做成 skill 的形态

本文方法论已固化为可执行技能 `project-memory-external`：扫描项目现有 CONTEXT.md/ADR（或从零初始化），检查术语表纪律（绑标识符/行数上限）与 ADR 格式（五段/否决项/代价），输出维护报告 + 补全建议。见本仓库 `skills/project-memory-external/SKILL.md`。
